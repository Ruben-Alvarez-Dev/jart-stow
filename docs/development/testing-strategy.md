# Testing Strategy

## Principles

- **No mock data.** All test data is generated by calling real system functions against a clean database.
- **Test behavior, not implementation.** Tests verify what the system does, not how it does it.
- **Test against real infrastructure.** Use real SQLite, not mocks.

## Layers

### Unit Tests (Go + Python)

- **Domain logic:** Pure functions, no I/O. Fast, deterministic.
- **Services:** With real SQLite (in-memory for Go, temp file for Python).
- **Parsers/Validators:** Input edge cases.

### Integration Tests (Go)

- **Adapters:** `TMUtilAdapter` tested with `tmutil` on macOS. `CCCAdapter` tested with a temporary `Exclusions.txt`.
- **Daemon:** FSEvents integration tested with real filesystem operations.
- **CLI:** Commands tested via `exec.Command` on the built binary.

### End-to-End (Manual + Future Automation)

- Install daemon, create a project, verify exclusion.
- Enable junk category, scan, approve items, verify cleanup.
- These are performed manually during development and documented as release checklists.

## Coverage Targets

| Module | Target |
|---|---|
| `internal/domain/` | ≥ 90% |
| `internal/services/` | ≥ 85% |
| `internal/adapters/sqlite/` | ≥ 80% |
| `internal/adapters/tmutil/` | ≥ 70% |
| `internal/adapters/ccc/` | ≥ 70% |
| `api/app/domain/` | ≥ 90% |
| `api/app/infrastructure/` | ≥ 80% |
| CLI commands | ≥ 60% |
| TUI screens | Manual testing |

## Running Tests

```bash
# Go
go test -race -coverprofile=coverage.out ./...
go tool cover -func=coverage.out

# Python
cd api && pytest --cov=app --cov-report=term
```

## CI Enforcement

- All tests must pass before merge.
- Coverage reports are generated but not blocking in CI (enforced locally).
- `golangci-lint` and `ruff` must pass with zero issues.
